## v1.3.0 - 2026-11-08


### version

#### Changed

- **`trellis version apply --pre` now writes incremental notes for each candidate.** Trellis archives candidate fragments and removes them from `unreleased`, so later candidates include only new changes. `--pre none` combines the target version's archived changes with any remaining fragments for the final rollup. Earlier candidate notes stay unchanged.

  `fragments_retained: true` now means archived for the final release, not left in `unreleased`. Commit the new `.changes/<package>/v<prerelease>.toml` archives alongside the Markdown sections.

### release

#### Added

- **`trellis release pr --auto-pre` continues committed candidates without implicit stable promotion.** It uses the current label only when no explicit or resumed mode applies. Packages keep separate version bases, and stable packages join through the normal plan. Conflicting labels produce an error. Unchanged release content does not create another candidate; use `--pre none` explicitly to promote.

- **`trellis release pr --resume` preserves a pending release's original request.** Later updates retain its candidate label, promotion choice, and per-package targets. Explicit options replace only the supplied fields; stable packages joining promotion keep their targets. Each preparation commits native intent in `<changelog.dir>/release.toml`. Fork PRs cannot supply intent, and stale or conflicting state fails before replacement.

- **`trellis release pr` reports structured outcomes for CI.** `--json` emits `trellis.release_pr/1`; `--github-output` emits records suitable for `$GITHUB_OUTPUT`. Both distinguish `prepared`, `unchanged`, and `no_changes`, include the package plan and available PR identity, and identify preparation as `created` or `updated`. Errors remain nonzero. Condition follow-up generation on `outcome == 'prepared'` without a separate planning command.

- **`trellis release pr --skip-unchanged` skips unchanged release preparation.** Added, edited, and deleted fragments or release-owned source changes permit preparation; unrelated docs and excluded examples do not. Bundled sources count for their release owners. Native state and verified legacy candidate history provide baselines. Deleting all pending content without a valid replacement plan fails. `--force` bypasses skipping, not validation; stable promotion still rolls up candidate fragments.
