## v1.5.0 - 2026-11-12


### trellis

#### Added

- **`[tools.trellis.adapter]` supports packages with non-Gleam manifests.** Set the required `manifest` key to a package-relative `.toml`, `.json`, `.yaml`, or `.yml` file. Optional `name` and `version` keys select dotted field paths, defaulting to `name` and `version`. Both fields must exist; JSON and TOML require strings. Omit `members` to discover packages automatically, including the workspace root.

  Configure adapters in root `trellis.toml` or `gleam.toml`, but never both. Gleam workspaces still use `gleam.toml`. Adapter manifests supply no dependency edges, so version bumps do not propagate between packages.

### run

#### Changed

- **`trellis run` rejects undeclared Gleam tasks in adapter workspaces.** To use `build`, `test`, `check`, `docs`, `deps`, `format`, or `clean`, define a command under `[tools.trellis.tasks]`. Custom tasks can override built-in names. The error lists declared tasks, and `trellis exec` remains available for arbitrary commands.

### changelog

#### Added

- **`changelog check` previews can show fragment commits and issue references.** Custom `change_format` templates receive `commit` and structured `issues` extracted from the subject of the commit that added each fragment. Templates construct the links; the default output and fragment format are unchanged.

  Missing or ambiguous local history leaves `commit` null and `issues` empty. Trellis does not fetch history or call an API, and optional lookup failures do not fail the check.

### version

#### Added

- **`trellis version apply` updates the configured adapter version field.** JSON and YAML edits preserve comments, key order, whitespace, and quote style. Missing fields, mappings, sequences, and ambiguous duplicate keys are rejected before release files change. JSON and TOML version fields must be strings. YAML block scalars and aliases cannot be rewritten; use a plain or quoted version string.

  Adapter version bumps leave Gleam `manifest.toml` lockfiles unchanged.

- **`version apply` preserves fragment source links through prerelease promotion.** Custom `change_format` templates receive an optional `commit` and structured `issues` from the fragment's source commit subject. Prerelease archives store these records before consuming fragments, so the final release keeps the original references rather than using the release commit.

  Old archives remain valid without metadata. Missing history or invalid optional metadata does not block a release. Default changelog output, version bumps, and existing JSON schemas are unchanged.

### init

#### Added

- **`trellis init` detects existing workspace configuration in `trellis.toml`.** It refuses initialization when `[tools.trellis]` already exists at the repository root or an ancestor, without creating a second configuration in `gleam.toml`. It also rejects `[tools.trellis]` in a discovered Gleam package's `trellis.toml`; keep workspace configuration at the root.

### release

#### Added

- **`release pr --prepare-command` generates and validates files before the release branch push.** Run a caller-supplied shell command after versions are applied so generated docs and consumer locks enter the same commit. A failed command stops preparation before remote changes. With unchanged release inputs, the command still runs: stale files on a pending PR are repaired without changing its proposed versions, and a clean rerun leaves the branch and PR unchanged.

#### Fixed

- **`trellis release pr` waits for GitHub to report a successfully pushed head.** Updating an existing release PR now retries briefly when GitHub still reports its previous commit. Closed or retargeted PRs, changed PR identity, and unexpected heads still stop preparation. If finalization fails after the push, the error states that the branch was pushed but PR finalization remains incomplete; no structured success output is emitted.

### publish

#### Changed

- **`trellis publish` rejects adapter workspaces instead of invoking `gleam publish`.** Adapter packages default to the `git_only` lifecycle, which supports changelogs, versions, and Git tags without Hex publishing. `[tools.trellis.publish.lifecycle]` rejects `hex` as either the default or a package override in an adapter workspace.

### lockfile

#### Changed

- **`trellis lockfile refresh` rejects adapter workspaces instead of invoking `gleam deps download`.** Adapter support does not add dependency resolution or lockfile generation for non-Gleam packages; use your package manager to update their dependencies.

### pin

#### Changed

- **`pin` refuses adapter workspaces without reading or changing unrelated Gleam manifests.** This applies to the default pin operation and `--check`, `--update`, and `--unpin`.

### doctor

#### Added

- **`trellis doctor` validates adapter manifests and requires semantic versions.** Package names do not need to match their directory names. Changelog, fragment, exclusion, and tag-collision checks still run.

  Adapter workspaces skip Gleam lockfile, pinned-dependency, shared-dependency, and toolchain checks. The `checked:` preamble names the adapter manifest and omits Gleam-only checks.
