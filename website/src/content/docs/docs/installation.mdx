Prebuilt binaries need no Rust toolchain. Releases include SLSA build provenance
attestations and binaries for Linux (glibc) and macOS on x86_64 and aarch64,
and Windows on x86_64.

To run Gleam tasks, install Gleam and the tools your target needs, such as
Erlang/OTP or a JavaScript runtime.

## Choose an installation method

- **Install on this computer:** use the [shell installer](#shell-installer)
  on Linux or macOS, or the [PowerShell installer](#powershell-installer)
  on Windows. If you use Homebrew, [install from the tap](#homebrew).
- **Keep a team or CI on one version:** [pin with mise](#mise),
  or [pin the installer URL](#pinning-a-version-in-ci).
- **Build with Rust:** [install from source](#from-source).

## Shell installer

On Linux and macOS:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/tylerbutler/trellis/releases/latest/download/trellis-gleam-installer.sh | sh
```

## PowerShell installer

On Windows:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/tylerbutler/trellis/releases/latest/download/trellis-gleam-installer.ps1 | iex"
```

## Homebrew

```sh
brew install tylerbutler/tap/trellis
```

## mise

Use mise's [github backend](https://mise.jdx.dev/dev-tools/backends/github.html)
to install trellis and record its version in `mise.toml`. Commit that file to
share the pin with your team and CI:

<Code lang="sh" code={`mise use "github:tylerbutler/trellis@${TRELLIS_VERSION}"`} />

## From source

The crate is named `trellis-gleam` on crates.io; the installed binary is `trellis`:

```sh
cargo install trellis-gleam
# or straight from the repository:
cargo install --git https://github.com/tylerbutler/trellis
```

## Verifying it

Run these commands inside your Gleam repository. Trellis walks up to the first
`gleam.toml` with a `[tools.trellis]` table, or uses the git repository root
when no manifest has one. This excerpt uses the
[example workspace](https://github.com/tylerbutler/trellis/tree/main/tests/fixtures/basic):

<Code
  lang="console"
  code={`$ trellis --version
trellis ${TRELLIS_VERSION}

$ trellis doctor
checked: member globs resolve and every package has a parseable gleam.toml
checked: path dependencies stay inside the workspace; graph is acyclic
...
ok: 4 package(s) (1 workspace, 0 git_only, 3 hex), 3 warning(s)`}
/>

The example's warnings concern existing changelog history, which
`trellis doctor --fix` can import. For workspace settings, use the
[configuration guide](/docs/configuration/).

## Pinning a version in CI

The installer URLs above resolve `latest`. To pin a specific version, replace
`latest/download` with `download/v<version>`:

<Code
  lang="sh"
  code={`curl --proto '=https' --tlsv1.2 -LsSf https://github.com/tylerbutler/trellis/releases/download/v${TRELLIS_VERSION}/trellis-gleam-installer.sh | sh`}
/>

Prebuilt archives for every target are on the
[releases page](https://github.com/tylerbutler/trellis/releases).

## After installation

### Shell completions

The binary supplies completion candidates as you type, using its current flags
and the package names, task names, and changelog kinds in your workspace.

Add one line to your shell's startup file:

```sh
# ~/.bashrc
eval "$(trellis completions bash)"

# ~/.zshrc (after compinit)
eval "$(trellis completions zsh)"

# ~/.config/fish/config.fish
trellis completions fish | source

# ~/.elvish/rc.elv
eval (trellis completions elvish | slurp)

# $PROFILE (PowerShell)
trellis completions powershell | Out-String | Invoke-Expression
```

Evaluate the snippet on startup. Saving its output to a completions directory
can leave an incompatible script after a trellis upgrade.

Completing after `-C` uses the current directory, not the directory you passed.
`--bump` completes only the three bare levels, not the `<pkg>=<level>` form.

### Man pages

`trellis.1` and a page per subcommand ship inside the release archives under
`man/`. Neither the shell installer nor the Homebrew formula installs them
automatically, so point `man` at the extracted archive or install them yourself:

```sh
sudo mkdir -p /usr/local/share/man/man1
sudo cp man/*.1 /usr/local/share/man/man1/
man trellis
man trellis-run
```

Everything in those pages is also on the [CLI reference](/docs/reference/) page.
